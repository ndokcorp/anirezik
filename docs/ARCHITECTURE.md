# Архитектура AniRezik 0.3.1

Astro + строгий TypeScript, полностью статический GitHub Pages. Сборка не обращается к Shikimori. Исходный snapshot содержит 30 704 аниме; браузер никогда не получает его целиком.

## Разделение данных

- `src/data/catalog.json`: нормализованный источник сборки, читается Node fs без вывода огромного JSON-типа TypeScript. Исключён из корневого списка TS. После sync dev нужно перезапустить.
- `src/data/static-page-ids.json`: постоянные 3000 ID версии 0.2.2. Для них сохраняются прежние `/anime/slug/`, включая 16 исходных legacy URL. Для новых записей `animePath` формирует `/anime/?id=ID`.
- `search-index.bin`: компактные tuple-строки с именами/алиасами и данными карточек/фильтров, справочниками жанров/студий/типов; gzip при сборке. Распаковка стандартным DecompressionStream в Web Worker. `search-index.json` — запасной формат; подробных текстов, связей и URL API-постеров там нет.
- `/data/anime/ID.json`: отдельные подробности одного аниме; загружаются универсальной страницей. Связи сразу получают действующий локальный или исходный внешний адрес. API URLs изображений исключены из этих пакетов.
- `/data/cards/BUCKET.json`: компактные сводки по диапазонам ID/1000 для избранного. Не более трёх параллельных запросов и только нужные пакеты текущей порции.
- `image-index.json`: формат v2 `{images,sharded,buckets,experimental}`, небольшие локальные изображения и список доступных пакетов. `/data/images/BUCKET.json`: разрешённые удалённые URL для диапазона ID/1000; получаются только нужные пакеты, не более трёх одновременно. В публичном режиме unknown не попадает в пакеты. Локальный эксперимент помечен явно, не меняет реестры разрешений.

## UI

Главная — короткие подборки. Каталог SSR отображает 24 карточки; полный индекс не скачивается до поиска, фильтра, URL с параметрами или «Показать ещё». Worker ищет/фильтрует/сортирует, возвращает лишь текущую порцию. Во время применения фильтра старые карточки inert, чтобы ранний клик не открывал неверный результат. Динамический рендерер использует DOM/textContent, существующие классы и обработчики изображений/избранного.

Глобальный поиск тоже запускается по вводу. Одновременно работает один Worker на документ; основной поток не хранит десятки тысяч развёрнутых записей. Нормализация создаётся один раз на активную сессию Worker, ответы со старой revision игнорируются. Загрузка/ошибка видимы. Это поиск всего импортированного набора, не live-запрос к Shikimori.

`/anime/` — статическая оболочка: числовой ID, загрузка одного локального JSON, детали, реальные пропуски, источники, связи, избранное, состояния неправильного ID/404/отказа. Она noindex; SEO сохранено на прежних 3000 страницах. Клики и reload работают при обоих base paths. Новые страницы не требуют отдельного тяжёлого HTML.

Избранное v2 сохраняет все ID и неизвестные записи, миграцию v1 и резервный ключ; UI больше не зависит от полного поискового индекса. Делегированный обработчик работает и для динамических карточек. Отказ индекса не мешает сохранению.

## Импорт

`full-sync.ts` выполняет полный прямой проход по ID и отдельный обратный проход ID, сверяет множества, восстанавливает пропуски и проверяет отсутствующие связанные ID. Все типы/годы/статусы, censored:false; без рейтингового лимита. Пакеты проверяются перед кешированием. При ошибке snapshot не меняется. Промежуточный отчёт лежит в .cache, финальный — в catalog-coverage.json. Windows rename имеет ограниченные повторы при временной блокировке без удаления рабочего файла.

Обычный ограниченный sync сохранён для обслуживания изменяющихся/популярных записей, а не для заявления нового полного покрытия. Обновление полного набора явно запускается `npm run sync:full`. У каждого пакета исходное fetchedAt, у отчёта — окно фактических ответов. Кешированная повторная сверка не выдаётся за новые сетевые ответы.

## Изображения и видео

RemotePoster/Poster и клиентский helper используют разрешённые URL, lazy/async/фиксированные размеры, однократный fallback, без crossorigin. backdrop независим от poster; источник, подпись и лицензия отдельны. Unknown не активируется. Hero использует imageUrl для HTTPS и честную атрибуцию. Изображения не скачиваются тысячами при сборке.

Нет подтверждённых сторонних постеров или видеопровайдеров. Публичная сборка сохраняет исходные AI-иллюстрации и заглушки. `image-policy.ts` объединяет индивидуальный реестр и подтверждение источника целиком из `image-sources.json`, проверяет точные HTTPS origins и выбирает компактный/оригинальный URL. `image-mode.ts` разрешает эксперимент только при dev + явный флаг + не CI; middleware ограничивает hostname loopback. Флаг никогда не активирует эксперимент в статическом production. Видео-контракты/региональные проверки сохранены, фиктивный плеер не добавлен.

Все внутренние маршруты/ресурсы проходят через paths.ts. Тесты и проверки описаны в VALIDATION.md; схема данных/покрытие — SHIKIMORI.md, лицензии — POSTER_RIGHTS.md.

Дополнение по загрузке: изображения карточек раскрываются через IntersectionObserver только рядом с экраном (160 px), скрытые слайды hero загружаются при выборе. Неиспользуемый поисковый Worker завершается через 60 секунд, повторный поиск использует HTTP-кеш индекса. При замене карточек старые наблюдатели освобождаются.
