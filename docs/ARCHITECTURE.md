## Разделение данных

- `src/data/catalog.json`: нормализованный источник сборки, читается Node fs без вывода огромного JSON-типа TypeScript. Исключён из корневого списка TS. После sync dev нужно перезапустить.
- `src/data/static-page-ids.json`: постоянные 3000 ID версии 0.2.2. Для них сохраняются прежние `/anime/slug/`, включая 16 исходных legacy URL. Для новых записей `animePath` формирует `/anime/?id=ID`.
- `search-index.bin`: компактные tuple-строки с именами/алиасами и данными карточек/фильтров, справочниками жанров/студий/типов; gzip при сборке. Распаковка стандартным DecompressionStream в Web Worker. `search-index.json` — запасной формат; подробных текстов, связей и URL API-постеров там нет.
- `/data/anime/ID.json`: отдельные подробности одного аниме; загружаются универсальной страницей. Связи сразу получают действующий локальный или исходный внешний адрес. API URLs изображений исключены из этих пакетов.
- `/data/cards/BUCKET.json`: компактные сводки по диапазонам ID/1000 для избранного. Не более трёх параллельных запросов и только нужные пакеты текущей порции.
- `image-index.json`: формат v2 `{images,sharded,buckets,experimental}`, небольшие локальные изображения и список доступных пакетов. `/data/images/BUCKET.json`: разрешённые удалённые URL для диапазона ID/1000; получаются только нужные пакеты, не более трёх одновременно. В публичном режиме unknown не попадает в пакеты. Локальный эксперимент помечен явно, не меняет реестры разрешений.

## UI

Главная — короткие подборки. Каталог SSR отображает 24 карточки; полный индекс не скачивается до поиска, фильтра, URL с параметрами или «Показать ещё». Worker ищет/фильтрует/сортирует, возвращает лишь текущую порцию. Во время применения фильтра старые карточки inert, чтобы ранний клик не открывал неверный результат. Динамический рендерер использует DOM/textContent, существующие классы и обработчики изображений/избранного.

Глобальный поиск тоже запускается по вводу. Одновременно работает один Worker на документ; основной поток не хранит десятки тысяч развёрнутых записей. Нормализация создаётся один раз на активную сессию Worker, ответы со старой revision игнорируются. Загрузка/ошибка видимы. Это поиск всего импортированного набора, не live-запрос к Shikimori.

`/anime/` — статическая оболочка: числовой ID, загрузка одного локального JSON, детали, реальные пропуски, источники, связи, избранное, состояния неправильного ID/404/отказа. Она noindex; SEO сохранено на прежних 3000 страницах. Клики и reload работают при обоих base paths. Новые страницы не требуют отдельного тяжёлого HTML.

Избранное v2 сохраняет все ID и неизвестные записи, миграцию v1 и резервный ключ; UI больше не зависит от полного поискового индекса. Делегированный обработчик работает и для динамических карточек. Отказ индекса не мешает сохранению.

## Импорт

`full-sync.ts` выполняет полный прямой проход по ID и отдельный обратный проход ID, сверяет множества, восстанавливает пропуски и проверяет отсутствующие связанные ID. Все типы/годы/статусы, censored:false; без рейтингового лимита. Пакеты проверяются перед кешированием. При ошибке snapshot не меняется. Промежуточный отчёт лежит в .cache, финальный — в catalog-coverage.json. Windows rename имеет ограниченные повторы при временной блокировке без удаления рабочего файла.

CLI обычного sync вызывает maintenance.ts: created_at_desc/updated_at_desc, два сезона и вращающийся адресный список активных/недавних ID, бюджет 80 пакетов. Старый ограниченный syncCatalog оставлен только для совместимости и прежних тестов, CLI его не использует. Обновление полного набора явно запускается `npm run sync:full`. У каждого пакета исходное fetchedAt, у отчёта — окно фактических ответов. Кешированная повторная сверка не выдаётся за новые сетевые ответы.

## Изображения и видео

RemotePoster/Poster и клиентский helper используют разрешённые URL, lazy/async/фиксированные размеры, однократный fallback, без crossorigin. backdrop независим от poster; источник, подпись и лицензия отдельны. Unknown не активируется. Hero использует imageUrl для HTTPS и честную атрибуцию. Изображения не скачиваются тысячами при сборке.

Подключены постеры 20 сериалов TVmaze: `remotePoster` в индивидуальном `image-rights.json` хранит точную пару medium/original, ID/URL/название/дату источника и evidence. `image-policy.ts` проверяет эту запись через тот же `sourceApproved`/exact HTTPS origin/scope `image-sources.json`. При отзыве реестра возвращается прежняя иллюстрация/заглушка; original AI поля не заменены. Небольшие 20 записей используют существующий image-index и общий IntersectionObserver/кеш, без нового клиентского адаптера/API. `poster-credits.json` — отдельно атрибутированная коллекция TVmaze под CC BY-SA 4.0, ссылки доступны в About/Footer. Shikimori unknown остаётся выключен; подтверждённых видеопровайдеров нет. `image-mode.ts` разрешает эксперимент только при dev + явный флаг + не CI; middleware ограничивает hostname loopback. Флаг никогда не активирует эксперимент в статическом production. Видео-контракты/региональные проверки сохранены, фиктивный плеер не добавлен.

Все внутренние маршруты/ресурсы проходят через paths.ts. Тесты и проверки описаны в VALIDATION.md; схема данных/покрытие — SHIKIMORI.md, лицензии — POSTER_RIGHTS.md.

Дополнение по загрузке: изображения карточек раскрываются через IntersectionObserver только рядом с экраном (160 px), скрытые слайды hero загружаются при выборе. Неиспользуемый поисковый Worker завершается через 60 секунд, повторный поиск использует HTTP-кеш индекса. При замене карточек старые наблюдатели освобождаются.

## 0.4.6 — канонические адреса и проверяемое расширение

`animeRoute(shikimoriId)` в paths.ts определяет канонический `anime/ID/`; numeric shikimoriId остаётся единственным внешним ID тайтла. Стабильные ключи `shikimori:ID` в избранном/истории/прогрессе сохранены совместимыми: ID поставщика туда не подставляется.

3 000 существующих SSR-страниц генерируются под числовыми адресами. clean-anime-routes создаёт компактные совместимые legacy-документы (JS/meta replacement) и bootstrap для остальных записей. Bootstrap загружает прежний единый `/anime/?id=ID` и initAnimeDetail заменяет адрес через history.replaceState на числовой без повторной навигации. Это два HTTP 200, без серверного 301, и без цикла. Обе страницы содержат canonical только на числовой адрес; sitemap содержит числовые адреса. Остальной каталог и поисковый индекс не встраиваются в каждый bootstrap. В dev middleware выполняет эквивалентные перенаправления/внутренний rewrite; production — обычные файлы GitHub Pages.

Постеры: разрешённый Shikimori main → original → отдельно подтверждённый TVmaze того же ID → фирменная заглушка. У каждого шага конечная попытка; CDN URL с неизвестными правами не разрешаются. Три новые пары TVmaze записаны в реестр прав и машиночитаемые credits.

AniLiberty: маленький checked-in aniliberty-index дополняет прежние пять seeds. Runtime заново проверяет внешний ID, региональные/правообладательские флаги и отсутствие противоречий году/формату/явному сезону, затем получает фактические серии. Отдельный bounded sync получает максимум одну страницу и 1–10 полных релизов за запуск; необязательная очередь и курсор вне production. Секретов/потоков в компактном индексе нет. Kodik 39535 и подготовленная ветка 0.4.5 не меняются.

Уточнение стартового экрана 0.4.6: play центрируется абсолютно, подписи/continue находятся в независимом блоке ниже. Заголовок в видео не дублируется. Панель скрыта через visibility до has-started на всех ширинах; playedSelections в пределах текущего плеера сохраняет состояние старта при смене качества, без новых записей localStorage.

Мобильная история просмотров в 0.4.7 перенесена в шапку непосредственно перед меню. Нижняя панель сохраняет пять позиций и центральный поиск. Ссылка использует прежний history/ через paths.ts и прежнее хранилище.

## 0.4.8: AniLiberty catalog index

The existing AniLibertyApi now preserves validated pagination envelopes and supports official release batches. scripts/lib/aniliberty-sync.ts separates discovery, exact metadata/ID matching, approved-HLS validation and complete-index publication. The public index has 1,588 mappings and exclusions, no media URLs. Per-title runtime still retrieves fresh release details and region/copyright flags; no catalog-wide browser requests. Unknown formats/year, conflicting remakes/seasons and ambiguous IDs are quarantined. Full scans compare updated_at/fresh_at stamps and bounded TTLs; the API has no documented updated_since cursor.

The sync workflow persists sanitized state on codex/aniliberty-sync-state and resumes sequential bounded jobs. Completed candidates reuse the tested Pages artifact pipeline; failed or partial runs preserve the published index. A six-hour schedule is gated by ANILIBERTY_SYNC_ENABLED. See docs/research/RELEASE_0.4.8.md for counts, request policy and live verification. Fractional ordinal progression is retained without skipping missing integer episodes.
