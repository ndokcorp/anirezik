# AniRezik 0.4.3 — MultiPlayer

## Внедрено

В основном AnimePlayer (SSR и универсальный маршрут) источник расположен слева над видео. Отдельный селектор озвучки убран из видимого интерфейса; справа — реальные переводы текущего провайдера, поиск «Поиск озвучки», звёздочки избранного и подсветка активного перевода. Эпизоды имеют hover/focus/selected-состояния с акцентом #E7364B. На мобильном боковая панель переходит под видео. Элементы AniRezik не накладываются на iframe или рекламу; фиксированная нижняя навигация скрыта на время открытого iframe.

При смене источника HLS уничтожается, media src удаляется, либо удаляется прежний iframe. До действия пользователя ни iframe, ни поток не запускаются. Запоминается последний доступный источник; неизвестный/больше не доступный провайдер не создаёт фиктивной кнопки. Только реальные доступные источники попадают в список. Если источник не запускается, можно выбрать другой доступный.

В расписании: **ОЖИДАНИЕ НОВЫХ АНИМЕ**, более крупный жирный красный текст.

## Доступные провайдеры

- **AniLiberty**: сохранён прежний адаптер/API/HLS и точные ID. Источник доступен, когда его API подтверждает релиз, серии и отсутствие блокировок.
- **Kodik**: пользователь ранее предоставил переписку-разрешение и явно подтвердил Shikimori 39535, первый сезон/часть 1 (2021), 11 серий. Только это соответствие включено; оно приоритетно при отсутствии сохранённого выбора пользователя. [Запись разрешения](rights/KODIK_PERMISSION.md).
- AniVibe остаётся выключенным (кроме ранее опубликованной изолированной тестовой страницы). Alloha/Collaps не зарегистрированы, не имеют кнопок или вымышленных ссылок.

`kodik-mappings.json` содержит ручное точное соответствие. 15 переводов (13 озвучек и 2 варианта субтитров), их ID, количество эпизодов и ссылки взяты только из открытых metadata-атрибутов меню официального iframe этого релиза. Извлечения потоков, токенов и массового каталога нет. Сохранены предоставленные провайдером media ID/hash; ссылки других тайтлов не угадываются. Значение episode=2 проверено обычным открытием официального iframe. У каждого варианта меню этого релиза указаны 11 эпизодов. Проверка каждого перевода длительным воспроизведением не проводилась.

## Синхронизация серии/перевода

В короткой диагностике родительская страница получила от https://kodikplayer.com настоящее событие:

`kodik_player_current_episode` с `value.episode`, `value.season`, `value.translation.id` и `title`.

Обработчик не доверяет title из события: выбирает только уже разрешённый источник с известными ID. Проверяются точный origin, contentWindow текущего iframe, ключ события, типы полей, сезон, серия и ID перевода. Сообщения другого окна, старого iframe, неизвестного перевода/сезона и повреждённые данные игнорируются. Событие меняет подсветку эпизода/перевода и сохранённую выборку **без перезагрузки iframe**. Внешние кнопки/список, напротив, загружают точную ссылку выбранного перевода/серии.

В живой проверке подтверждено стартовое событие. Меню iframe реально меняло серию/перевод, но последующие события сразу после этих действий в коротком окне наблюдения не пришли. Поэтому мгновенная/полная синхронизация всех переходов не объявляется доказанной: внешний UI обновится, когда Kodik отправит подтверждённое событие. Длительное ожидание рекламы/повторная проверка видео не выполнялись. Готовый приёмник и оба изменения состояния проверены mock-iframe, включая отсутствие повторного запроса iframe на событии. Требуется уточнить у Kodik официальный контракт и момент отправки события (в том числе во время рекламы).

## Сохранение и совместимость

- `anirezik:player-provider:v1`: последний источник по аниме, максимум 500 записей.
- `anirezik:voice-favourites:v1`: избранные переводы, максимум 200. Избранное относится к ID перевода провайдера, не к вымышленному аккаунту.
- Прежний `anirezik:playback:v1` сохранён. Дополнительный `anirezik:playback-providers:v1` хранит до 400 позиций по паре аниме/провайдер. Первый iframe переносит прежний HLS-прогресс в эту защитную запись перед обновлением текущего выбора. null-позиция iframe не стирает время AniLiberty. Существующие миграции коллекции/каталога не менялись.
- Сбой localStorage не препятствует воспроизведению.

## Почему Kodik у YummyAnime красный

На [странице YummyAnime](https://old.yummyani.me/catalog/item/reinkarnaciya-bezrabotnogo-istoriya-o-priklyucheniyah-v-drugom-mire-2026-10-22) штатным меню выбран Kodik. Чтение DOM официального iframe подтвердило `customization=true`, собственные inline CSS для прогресса/громкости/HD/активных настроек с #ff6666 и вычисленный цвет play SVG rgb(255,102,102). Именно эти правила внутри iframe объясняют красный вид, а не внешняя рамка YummyAnime.

Обычная загрузка **того же полного URL** из настоящего origin AniRezik без подмены заголовков дала другой вычисленный цвет play SVG — rgb(254,254,254); customization=true остался и там. У URL были только параметры translations, only_episode, only_season, episode, skip_button; явного параметра цвета не обнаружено. Никакие доменные подписи или чужие API-ключи не переносились. Видео при сравнении темы не запускалось.

Это подтверждает различие оформления в разных контекстах встраивания. **Не доказано**, что конкретная причина — партнёрский кабинет, настройка Referer/домена, cookie или иной механизм Kodik. Один флаг customization не доказывает наличие публичного переключателя темы. Официальную документацию, разрешающую задать #E7364B через параметр/API, получить не удалось; [главная Kodik](https://kodikplayer.com/) направляет владельцев сайтов к support@kodikres.com.

### Можно ли получить тот же результат для AniRezik

Сам Kodik умеет выдавать красное оформление — это подтверждено. Возможность самостоятельно установить наш произвольный #E7364B пока **не подтверждена**. Внутренние элементы нашего iframe в этой версии **не перекрашены**. Внешний контейнер, собственный HLS-интерфейс AniRezik, эпизоды и список переводов имеют наш красный акцент.

`src/data/kodik-theme.json` хранит выключенную заявку на тему: accent #E7364B, controls #1B1B1B, secondary #282828, text #FFFFFF, timeline #2D2D2D. officialMechanism=null. Само изменение enabled не создаёт неизвестный API-контракт: активировать применение можно только после документации/настройки со стороны Kodik. Не было инъекций CSS/JS в чужой iframe, подмены ответов, обхода same-origin policy, изменения рекламы или потоков.

Необходимость партнёрского API-ключа для темы не установлена. Для текущего iframe ключ не используется. Если метод требует секрет, он не попадёт в Pages/браузер; потребуется разрешённая серверная выдача либо кабинетная настройка без клиентского секрета.

## Добавление Alloha / Collaps / другого источника

Независимый адаптер реализует VideoProvider.getSources по точному Shikimori ID; добавляется в approvedProviders только после прав, origins, региональных условий и доступного официального embed/API. У каждого источника должны быть реальные эпизоды/переводы. Нельзя назначить произвольный episode=1 целому сериалу ради обхода типизации. Для whole-release API без точных эпизодов сначала нужен явный отдельный контракт релиза.

Iframe-параметры задаёт адаптер через iframePolicy. Необязательный readStateEvent проверяет документированный/подтверждённый протокол провайдера и возвращает только существующий разрешённый источник. Основной плеер повторно проверяет origin/source и принадлежность результата. Если события/внешнее управление не поддерживаются, управление остаётся внутри провайдера; фиктивных переключателей не добавляем. Приватные API-ключи требуют backend, которого статический Pages не предоставляет.

Browser mock: SSR/универсальный маршрут, смена источника, единственный активный iframe/video, поиск/избранное после перехода, синхронизация по событию без перезагрузки, продолжение AniLiberty с 0:42, отсутствие Kodik у другого тайтла, расписание, 390 px. Старые точечные HLS/error/ID тесты прошли. Полный импорт не запускался.

Финально: npm run check — 0 ошибок/предупреждений; production build с /anirezik/ — 3020 страниц; 6 точечных unit-тестов и 3 browser-теста прошли. Те же browser-проверки прошли на корневом dev base и production preview /anirezik/. В клиентской сборке не найдены av_live_, X-Api-Key, GM.xmlHttpRequest или запросы Kodik с token; непроверенная отдельная seria/765426 в плеер не попала. Публикация выполняется штатным GitHub Pages workflow после серверных проверок.
