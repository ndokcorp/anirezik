# AnimeVost: предоставленное владельцем подтверждение

Дата получения: 27.10.2026. Владелец AniRezik прямо подтвердил согласие поставщика и приложил изображение ответа на вопрос о собственных озвучках AnimeVost и HLS/MP4 в HTML5-плеере AniRezik с указанием источника. Ответ: «Да без проблем, подключайте наши озвучки в плеер который вам будет удобно, рекламы даже нет!»

Основание — заявление владельца и предоставленная им переписка. Изображение не содержит проверяемых RFC822 headers/DKIM и оригинала письма: независимо аутентифицировать отправителя по скриншоту нельзя. Отображаемый отправитель не равен техническому подтверждению подлинности. Нельзя утверждать, что произведена такая проверка. Скриншот и личные данные в репозиторий не копируются.

Область: собственная озвучка AnimeVost в существующем AniRezik Player, атрибуция AnimeVost. Не сторонние дорожки, не передача прав на сами произведения, не доступ к закрытым API, не обход рекламы/авторизации/геоблокировок. Новые media origins требуют отдельной технической и правовой проверки. API на домене AnimeVost доступен без чужих ключей.

Технически проверены `/v1/search` и `/v1/playlist` через POST form, `/v1/last` через GET. Схема в anicli-api `dev/swagger/animevost.yml` сгенерирована из наблюдавшегося HTTP-трафика, не является опубликованным договором/официальным SLA. Числовой rate limit и гарантированный срок жизни ссылок неизвестны. Синхронизация последовательная, не чаще одного запроса в две секунды, с checkpoint и остановкой на ошибках; автоматическое расписание до уточнения лимитов выключено.

API playlist возвращает HTTP MP4 на `video.animetop.info`. Тот же путь по HTTPS проверен HEAD и Range: 200/206, video/mp4, MP4 ftyp, byte ranges, CORS `*`. Повышение схемы ограничено этим точным host; HTTPS ошибки не обходятся, прокси не используется. Внешние/неизвестные host отклоняются. Потоки запрашиваются свежими, ссылки не публикуются в статическом кеше и не сохраняются в localStorage.

API не сообщает отдельный список стран. Нельзя объявлять worldwide-доступ. Для этого отдельного провайдера региональные/медиа-ограничения исполняет исходный CDN в браузере (`media-enforced`); ошибки не проксируются и не обходятся. Это не `regionChecked: true` и не фиктивная страна `*`.
