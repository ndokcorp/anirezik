# AniRezik 0.3.0 — результат

24 октября 2026. Изменён существующий проект Astro; дизайн, логотип, прежние URL и избранное сохранены. Удалённая публикация не выполнялась: GitHub-репозиторий и Pages пока не подключены.

## 1. Реальный размер каталога

**30 704 уникальных аниме**, вместо 3000 в предыдущем локальном снимке. Сохранены все 3000 прежних ID и их статические адреса. Для остальных работает `/anime/?id=ID`, например редкий тайтл 1933 года «Лиса против Енота» (3929). Подробности берутся из статического JSON, без запроса Shikimori при открытии страницы.

## 2. Полнота Shikimori

Официальный GraphQL, два независимых прохода: 615 страниц `order:id` с метаданными и 615 страниц `order:id_desc` с ID. По 50 записей, `censored:false`, без ограничения годов, рейтинга, статуса или типа. Оба списка содержат одинаковые 30 704 ID. Дублей, обнаруженных пропусков и отсутствующих связанных ID — **0**. Скрытые/удалённые записи API не перечисляет: их число неизвестно, 100% внутренней базы не заявляется.

Типы: TV 8783, фильмы 5099, OVA 4287, ONA 4438, TV-special 817, special 1768, music 4567, CM 517, PV 363, неизвестный тип 65. Первый проход потребовал 1230 последовательных запросов с задержкой около секунды; повторная проверка использовала 1230 кешированных пакетов и **0** новых запросов. Есть продолжение, проверка пакетов, обработка 429/Retry-After, ограниченные повторы, ремонт пропусков и атомарная замена проверенного снимка.

[Первичный сетевой отчёт](research/full-scan-first-0.3.0.json), [итог покрытия](../src/data/catalog-coverage.json), [механизм импорта](SHIKIMORI.md).

## 3. Поиск

Локальный поиск по всем 30 704 импортированным аниме: русские, английские, японские и альтернативные названия, частичные совпадения, фильтры и сортировка. Живого глобального API-поиска нет. Поиск работает в Web Worker; компактный индекс загружается при взаимодействии. Готовый gzip-пакет — 2 341 345 байт, запасной JSON — 5 933 420. Описания, связи и URL постеров не дублируются в индексе или каждом HTML. Каталог показывает 24 карточки за раз; избранное получает только нужные пакеты карточек. Worker освобождается через 60 секунд простоя.

## 4. Внешние постеры

Технический тракт реализован: `RemotePoster`, обычный HTTPS `img`, lazy/async, фиксированные размеры, cover, отдельный реестр разрешений, однократная нейтральная заглушка. `crossorigin` не добавляется. Карточки раскрывают `src` рядом с экраном; тысячи изображений одновременно не запрашиваются.

Пользователь сообщил: **«Разрешений пока нет»**. Поэтому настоящие внешние постеры **не включены**. Исходные URL найдены у 28 757 записей API, но доступность URL не подтверждает права. Реестр `image-rights.json` не расширен неподтверждёнными разрешениями.

## 5. Результаты выборки изображений

В Chromium и WebKit декодируются **30/30 собственных тестовых SVG** через перехваченные тестовые HTTPS URL. Проверены размеры, lazy/async, отсутствие crossorigin, abort и отсутствие бесконечного повторения fallback. Это проверка программного тракта, **не 30 настоящих внешних аниме-постеров**. Успешно проверенных на стороннем CDN разрешённых постеров — **0**. Также проверен реальный отказ запроса существующего оригинального WebP и декодирование заглушки.

[30 реальных образцов метаданных API](research/poster-source-sample-0.3.0.json) включают популярные, старые, редкие аниме и фильмы; этот список не является лицензией или отчётом декодирования внешних файлов.

## 6. Разрешённые изображения

Новых внешних изображений с подтверждёнными правами — **0**. Сохранены 16 прежних подписанных AI-иллюстраций, существующий широкий арт и нейтральные заглушки. Новые заменяющие постеры не генерировались. Право на коммерческое использование чужих персонажей этими иллюстрациями не подтверждается.

Исследованы условия Shikimori, TMDB и AniList. Публичный API и отсутствие прямого запрета не приняты за разрешение на hotlinking, кеширование или коммерческую публикацию каждого изображения. Подготовлен [конкретный запрос Shikimori](SHIKIMORI_REQUEST.md), он **не отправлен**. Для TMDB нужны аккаунт/принятые условия/ключ и проверка разрешений; коммерческие условия отдельные. [Правовой разбор с источниками](POSTER_RIGHTS.md).

## 7. Широкие баннеры

Разделены `posterUrl`, `backdropUrl`, `imageSource`, `imageAttribution`, `imageLicenseStatus`. Используется разрешённый широкий арт; при его отсутствии — подписанная размытая композиция из разрешённого постера или нейтральный фон. Вертикальное изображение не выдаётся за настоящий backdrop. TMDB документирует отдельные backdrops, но без аккаунта и подтверждённых условий они не получались и не подключались.

- Проверены старые страницы, прямой вход и reload новых страниц, избранное/миграция, редкие тайтлы вне прежних 3000, отказы индекса/подробностей/API/изображений, возобновление импорта и 10 ширин 320–1920 px. Тесты не отключались.

Сборка читает локальный snapshot и не требует доступа к API. По локальным размерам есть запас относительно опубликованного лимита Pages 1 ГБ, но удалённый CI/Pages ещё не проверен. [Методика и результаты](VALIDATION.md).

## 9. Производительность

Production localhost, новый Chromium без кеша. Desktop: FCP **180 мс**, load **219 мс**, первый поиск с индексом **848 мс**, последующие **15–28 мс**. Начальные данные **933 895 байт**; индекс/подробные JSON до взаимодействия не запрашиваются.

Эмуляция телефона 390×844, CPU ×4, latency 400 мс, download 50 000 байт/с: FCP **1756 мс**, load **16 691 мс**, начальные данные **788 587 байт**, 7 запросов изображений. Первый поиск требует **49 160 мс** на загрузку/обработку полного индекса; повторные — **47–138 мс**. Это существенное оставшееся ограничение, а не мгновенный холодный поиск. По сравнению с замером до ограничения prefetch: начальные данные 1 065 754→788 587 байт, load 22 287→16 691 мс, запросы изображений 12→7.

Основной JS heap до поиска ~2.17 МиБ; сумма working sets процессов Chrome desktop 274→442 МиБ, mobile 385→549 МиБ. Она может дважды учитывать общую память и не равна памяти приложения или Android. В 90 измеренных кадрах прокрутки интервалов >50 мс не было. Это локальная эмуляция, не гарантия для физического слабого телефона. [Сырые измерения](research/performance-0.3.0.json).

## 10. Ограничения и следующая версия

Для настоящих постеров нужны подтверждённые условия источника; для регулярного API-обслуживания — регистрация Shikimori-приложения владельцем и его User-Agent. Для публикации нужны репозиторий и Pages. Следующая техническая задача — уменьшить холодную загрузку поиска посредством более мелких пакетов, затем проверить реальные слабые телефоны и доступность из российских сетей. Обязательных платных сервисов или Cloudflare нет. Онлайн-видео, аккаунты и недоступные функции не выдаются за готовые.
