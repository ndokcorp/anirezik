# Поиск AniRezik 0.3.0

Охват — **30 704 импортированных аниме**. Поиск локальный по снимку, не live-запрос Shikimori. Точное совпадение названия/алиаса выше частичного; поддержаны русские, английские, японские имена, алиасы, Unicode NFKC, ё/е, регистр и все токены запроса. Enter, стрелки, Escape и мобильный поиск сохранены.

## Загрузка и память

Главная и первые 24 карточки каталога не скачивают индекс. При первом вводе/фильтре запускается отдельный Web Worker и загружает **search-index.bin (2 341 345 байт)** — готовый gzip компактного индекса. DecompressionStream распаковывает его внутри worker; при отсутствии этого стандартного API используется search-index.json (5 933 420 байт). .bin выбран, чтобы не зависеть от заголовка Content-Encoding хостинга. Обычные браузерные HTTP кеши применимы к обоим статическим ресурсам.

Tuple-формат убирает повторяющиеся имена ключей и справочные строки студий/жанров. Нет полных описаний, связей, дат и исходных URL постеров. Worker разворачивает индекс/нормализацию один раз на активную сессию Worker; основной поток получает максимум 6 подсказок или запрошенную порцию карточек. Подробности одного аниме идут отдельным JSON только при его открытии. Все языковые варианты проверены roundtrip-тестом компактного формата.

Холодный поиск включает время загрузки полного индекса; на медленной сети это заметное ожидание с видимым состоянием. Мгновенность относится к повторному поиску после загрузки, а не обещанию мгновенно скачать 2.34 МБ на любом соединении. Измерения — VALIDATION.md и research/performance-0.3.0.json.

## Каталог и избранное

SSR каталога содержит ровно 24 карточки. Фильтры/сортировки и URL-состояние сохранены. «Показать ещё» добавляет следующую порцию по действию пользователя; автоматического скачивания десятков страниц нет. На время применения фильтра старые карточки inert: раннее нажатие не открывает тайтл из предыдущей выборки. Нормализация и сортировка не блокируют основной поток.

Избранное не требует всего индекса: загружает компактные пакеты только для сохранённых ID в текущих 24/48/... записях, не больше трёх одновременно. Ошибки поиска не мешают записи localStorage; неизвестные старые ID и резерв v1 сохраняются.

## Адреса и ошибки

3000 прежних статических SEO-адресов сохранены через static-page-ids.json. Новые результаты ведут на `/anime/?id=ID`, существующую оболочку с локальным `/data/anime/ID.json`. Прямой вход, reload, base `/anirezik/`, связи и избранное проверяются. Некорректный ID не запрашивает данные; отсутствие записи/503/timeout показывают честное сообщение. Никаких фиктивных `/anime/shikimori-ID/` для несобранного HTML.

При отказе индекса показана ошибка и доступен повторный ввод; меню, 24 исходные карточки и сохранение избранного работают. Ответы устаревших запросов не заменяют новые. Внешние постеры не подмешиваются из сырых API URL.

## История проверки live API

В 0.2.2 реальный fetch с HTTPS GitHub Pages вернул GTO через CORS в Chromium/WebKit. Chromium проигнорировал User-Agent приложения, WebKit отправил его: [исходный отчёт](research/browser-api-0.2.2.json). В 0.3.0 эта интеграция не включается и для полного локального снимка не нужна. Будущий live поиск потребует отдельного согласованного backend/идентификации; варианты с оговорками о РФ — GLOBAL_SEARCH.md. Cloudflare не является обязательной зависимостью.

Дополнение по загрузке: изображения карточек раскрываются через IntersectionObserver только рядом с экраном (160 px), скрытые слайды hero загружаются при выборе. Неиспользуемый поисковый Worker завершается через 60 секунд, повторный поиск использует HTTP-кеш индекса. При замене карточек старые наблюдатели освобождаются.
