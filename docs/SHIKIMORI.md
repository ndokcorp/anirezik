## Официальный API

Проверен `https://shikimori.io/api/graphql`, [документация](https://shikimori.io/api/doc). Живая introspection подтвердила `OrderEnum`: id/id_desc, ranked, kind, popularity, name, aired_on, episodes, status, random, ranked_random, ranked_shiki, created_at/created_at_desc, updated_at/updated_at_desc. У animes есть page/limit (максимум 50), kind/status/season/rating/origin/genre/studio/ids/excludeIds/search/censored. Отдельного total count в использованном ответе нет. Introspection тоже ограничена глубиной запроса: схемы запрашивались небольшими запросами.

Полный импорт использует стабильную сортировку **id**, без фильтра kind/status/season/score, `censored:false`. Поэтому включает TV, фильмы, OVA, ONA, TV specials, specials, music, CM, PV и записи с неизвестным kind. Возрастные категории остаются метаданными; изображения/описания/видео этим не разрешаются.

Фактический состав: TV 8783, фильмы 5099, OVA 4287, ONA 4438, TV-special 817, special 1768, music 4567, CM 517, PV 363, неизвестный тип 65. Старые/низкорейтинговые записи не отсекаются.

## Что означает полнота

**Все 30 704 обнаруженных ID импортированы; известных недоступных/неразрешённых ссылок на связанные anime — 0.** Это согласованность двух обходов публичного API в зафиксированном окне. Нельзя вывести 100% всей внутренней базы Shikimori: скрытые, удалённые, ограниченные правами/клиентом записи API может не перечислять. Их общее количество неизвестно. Числовые пропуски ID не считаются пропущенными аниме: ID могут принадлежать удалённым записям.

После завершённого прохода связанные ID, отсутствующие в карте, запрашиваются пакетами по 50; недоступные фиксируются отдельно. Если прямой/обратный наборы расходятся, есть дубли или завершение не достигнуто, рабочий snapshot сохраняется. Исходные старые страницы сохраняются даже при выпадении записи из будущего API.

## Запуск/восстановление

```sh
npm run sync:full
npm run sync:anime
npm run sync:anime -- --ids=1,5114
```

Полный режим — full-sync.ts; ограниченный старый sync — обслуживание популярных/изменяющихся данных с сохранением остальных. Кеш проверенных пакетов в .cache/shikimori, TTL 7 дней полного обхода. Прогресс full-progress.json вне src, чтобы быстрый replay не заставлял dev watcher перечитывать десятки мегабайт. При прерывании повторить ту же команду: готовые пакеты сохраняются. Сборка offline. После sync перезапустить dev.

1 запрос/с ниже опубликованных 5 rps/90 rpm. 20-секундный timeout, ограниченные сетевые/5xx повторы, Retry-After для 429; 401/403 не обходятся. Слишком большой Retry-After прекращает запуск. --force не отменяет лимиты и может потребовать повторных 1230 запросов: без необходимости не применять. Файлы пишутся через temporary + backup + rename, без удаления рабочего snapshot. На Windows временные EPERM/EBUSY/EACCES получают ограниченные файловые повторы.

SHIKIMORI_USER_AGENT должен содержать имя зарегистрированного OAuth2-приложения владельца до регулярной эксплуатации. В исследовательском импорте отправлялось честное имя AniRezik/0.3.0; регистрация владельцем не подтверждена, токен для публичных полей не потребовался. Никаких браузерных UA-обходов и публичных CORS-прокси нет. В браузере поиск и подробности используют только локальные статические данные.

## Права и автоматизация

Публичность API не является лицензией на изображения/чужие описания. 28 757 записей имеют poster.mainUrl/originalUrl, однако они хранятся лишь как исходные метаданные. Повторно проверены terms/for_right_holders: универсальная лицензия не найдена, пользователь подтвердил отсутствие разрешений. POSTER_RIGHTS.md и SHIKIMORI_REQUEST.md содержат условия и неотправленный запрос.

Существующий workflow выключен до настройки SHIKIMORI_SYNC_ENABLED и User-Agent. Ежедневно — обслуживание; manual workflow_dispatch предлагает maintenance/full. Полный прогон с кешем, проверки, PR, затем публикация только после слияния. Отчёт покрытия коммитится вместе со snapshot. Удалённый запуск не выполнялся: репозитория ещё нет.
