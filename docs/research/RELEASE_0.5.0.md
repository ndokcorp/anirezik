# 0.5.0 — полный обход AnimeGO

Статус: очередь полного обхода запущена; опубликованная версия пока 0.4.9, 23 AnimeGO/CVH аниме. Нельзя считать промежуточную партию полным покрытием.

`scripts/sync-animego-catalog.py` обрабатывает замороженный sitemap (3 075 URL), затем уникально сопоставленные страницы и наблюдаемые списки серий. Используются существующие парсер метаданных/строгое сопоставление и AnimeGO/CVH VideoProvider. GUI и AniLiberty/Kodik не меняются. Сопоставление требует точного оригинального/английского имени/алиаса, года и формата; неоднозначные ID, несколько страниц на один Shikimori ID, неполные форматы и неизвестные серии требуют проверки. Ремейки и части не выбираются нечётким поиском.

Запросы последовательные, минимум 1,5 с; партия 1–500 HTTP-запросов. Ошибки 5xx/сети повторяются максимум два раза с задержкой и учитываются в бюджете. 403/429/challenge останавливают очередь без обхода. Только подтверждённые 404/410 становятся отсутствующей страницей/серией; ошибка не становится not-found.

SQLite сохраняет каждую страницу, сопоставление и минимальный ответ по серии. Это не копии HTML, изображений, описаний или медиапотоков. Кешируются только фактически выданные AnimeGO HTTPS iframe, с отдельными namespaced translation IDs. Kodik/AniBoom фиксируются как найденные названия провайдеров, но не включаются этим адаптером; разрешение на AnimeGO bridge не используется для копирования чужого API или publisher ID.

`scripts/animego-checkpoint.py` сохраняет сжатый согласованный SQLite snapshot в отдельную ветку `codex/animego-sync-state`. `.github/workflows/sync-animego.yml` восстанавливает его и последовательно запускает следующую разрешённую партию. Нет параллельного запроса тысяч страниц, повторного импорта Shikimori или API-запросов из браузера. На блокировке/ошибке после ограниченных повторов сохраняется курсор; workflow завершается с ошибкой вместо вечного цикла.

Публикация разрешена только после полного прохода: `apply-animego-candidate.py` проверяет все ID/метаданные/сочетания серия–перевод/точный origin и отсутствие посторонних параметров. Затем выполняются npm run check и build; прежний опубликованный кеш сохраняется при ошибке. Строго ограниченный commit кеша и выпуск 0.5.0 создаются только после успешной сборки. Проверяется отсутствие конкурирующего изменения main. Страница отчёта данных: `src/data/animego-sync-report.json` после завершения. Полные повторные браузерные тесты не запускаются: UI/плеер не меняются, по прямому запросу пользователя проверяются данные и сборка.

Курсор и observed responses обеспечивают возобновление текущего полного снимка; регулярный новый полный цикл автоматически не начинается. Обновление sitemap или Shikimori snapshot требует отдельного согласованного снимка/пересопоставления. Таким образом, отчёт не обещает непрерывную актуальность или вечную доступность источника. Региональные ограничения/реклама остаются у оригинального iframe. Реальное воспроизведение до расширения проверено для трёх тайтлов; эти три проверки не выдаются за запуск всех новых серий.

Ручной запуск/продолжение: `python scripts/sync-animego-catalog.py --max-requests=500`. Для Actions — workflow **Full approved AnimeGO catalog coverage**. Значения API-секретов не нужны.
