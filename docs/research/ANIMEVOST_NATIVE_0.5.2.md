# AnimeVost → существующий AniRezik Player, 0.5.2

## Что реализовано

Отдельный AnimeVost VideoProvider использует прежний native AniRezik Player: play/pause, seek, громкость, качество, серии, fullscreen, сохранение прогресса и выбор провайдера. CSS и дизайн не менялись. AniLiberty, Kodik и 97 CVH-соответствий сохранены. [Права и пределы проверки отправителя](../rights/ANIMEVOST_PERMISSION.md). Скриншот и личные данные не публикуются.

Статический индекс содержит **2 736 соответствия**, а не 2 736 лично просмотренных видео. Resolver при открытии страницы запрашивает текущий playlist официального домена AnimeVost. Источник появляется только если API реально вернул эпизоды с точными разрешёнными номерами и валидными media URLs. Ошибка/пустой ответ/неизвестный origin не включают заглушку или iframe. API не даёт отдельного списка студий: показывается имя поставщика AnimeVost, поле dubbingStudio остаётся null. Не заявляем тысячи уникальных студий или альтернативных переводов.

Ссылки не записываются в статический JSON, HTML или localStorage. API не требует собственного ключа в проверенных запросах, CORS `*` позволяет работать с Pages без Python-backend. MP4-варианты std/hd получены непосредственно из playlist; меню показывает SD/HD, потому что размеры старых файлов могут отличаться от 480p/720p; HLS/DASH здесь не наблюдались. Гарантированного срока жизни ссылок API не сообщает: краткий память-кеш — политика клиента, не срок действия поставщика. Для обновления устаревшей открытой сессии нужна новая загрузка страницы. Видео не проксируется.

## Каталог и масштабирование

Вместо 30 704 поисков использован `/v1/last?page=N&quantity=40`: последовательные запросы, checkpoint после каждой страницы, дедупликация release ID. Получено **3 602 уникальных релиза**; API сообщает 3 611, но страница 91 вернула лишь две записи. Очередь остановилась на проверке полноты, `complete=false`, расхождение 9 записей не скрыто. Ошибок 403/429 не было, ограничения не обходились. Не перезапускаем полный обход ради исправления счётчика.

Matcher сравнил существующий каталог из 30 704 Shikimori ID с уже полученными метаданными: точный нормализованный русский/оригинальный/альтернативный заголовок, точный год и формат. Цифры сезонов/частей не удаляются, несколько совпадающих Shikimori ID или несколько релизов для одного ID исключаются. Дополнительно исключены 67 конфликтов диапазона эпизодов: поставщик вернул номера выше ожидаемого количества серий Shikimori; это может быть объединение сезонов или устаревшие метаданные. Номера не сдвигаются искусственно. **2 736 уникальных кандидата**, **866 остальных релизов требуют проверки** (нет точного соответствия/серий либо неоднозначность). Это не 866 доказанно отсутствующих аниме.

Из 2 736 ID **1 458 отсутствуют в прежнем объединении индексов** (1 664). Это потенциальное расширение доступности, а не 1 458 видеопроверок. Для индекса указано **43 776 номеров эпизодов по метаданным**; наличие каждого файла и все страны не проверены.

`python scripts/sync-animevost.py --max-pages 5` продолжает сохранённую очередь, не запускает параллельные потоки. Сохранённая ошибка блокирует сетевое продолжение; `--max-pages 0` повторяет только офлайн-matching. `--publish-exact` требует одобренного direct playback и записанного успешного cross-browser пилота, обновляет ID для ленивого resolver, не ставит playbackVerified всем записям. Неполный снимок не удаляет прежние связи. `--publish-reviewed` позволяет включить только индивидуально проверенные ID. Workflow `sync-animevost.yml` собирает кандидатов/сохраняет checkpoint как artifact/cache, ничего не публикует; расписание выключено до уточнения лимитов.

Добавление нового аниме не требует F12 или ручного iframe: обновление метаданных → точное соответствие → индекс ID → свежий playlist при открытии. Для неоднозначных сезонов требуется проверка, а не угадывание.

Позже добавлен только выбор основного playbackUrl как fallback для источника с качествами SD/HD; прежний выбор числовых качеств AniLiberty сохранён.

## Проверки и выпуск

TypeScript/Astro, production build, профильные unit и штатный Pages workflow успешно пройдены. Production deploy и проверка реального видео на публичном origin подтверждены ниже. Наличие ветки или локального build не использовалось как доказательство публикации. [Диагностика с точными границами](../diagnostics/ANIMEVOST_NATIVE_0.5.2.json).

Ограничения: расхождение upstream total; неизвестные договорные rate limits/expiry; каждый из 2 736 тайтлов, все эпизоды, страны и качества не проигрывались. Изменение CDN-origin блокирует поток до проверки, а не включает чужой host. API доступность и соответствие не подменяют видео-проверку; счётчики этих этапов разделены.

## Подтверждённая публикация

**Deploy успешен:** [GitHub Pages workflow](https://github.com/ndokcorp/anirezik/actions/runs/40550147239), production commit `b8573a00f8063e6b6e54b8ce5607aed0c4a01b7c`. Финальные check/build/unit, UI Chromium/Firefox/WebKit и отдельное реальное видео на собранном `/anirezik/` прошли до deploy. Обычные UI-тесты используют изолированный пустой API fixture, реальные видеотесты не подменяют сеть.

На публичном origin после deploy реально проиграны [Аля 54744](https://ndokcorp.github.io/anirezik/anime/54744/) до 31.6 сек, [Solo Leveling 52299](https://ndokcorp.github.io/anirezik/anime/52299/) до 41.4 сек, [Одна комната 56838](https://ndokcorp.github.io/anirezik/anime/56838/) до 38.3 сек. Проверены mute/unmute, пауза и сохранение: повторное открытие Али показывает «Продолжить с 1:02 · AnimeVost». AniLiberty 52299 также проигрался до 43.2 сек в 720p; клавиша вправо переместила время до 53.3 сек, затем выполнено переключение на AnimeVost. Шесть опубликованных числовых URL отвечают HTTP 200; HTTP-ответ не включён в счётчик видеопроверок.

Вне начального пилота дополнительно реально просмотрены 56838 и 20 (Наруто, локально до 19.1 сек, 640×363). Всего **6 аниме, 7 различных пар аниме/эпизод, 6 подтверждённых вариантов дорожки поставщика**. Три ранее отсутствовавших в индексе аниме получили наблюдавшийся первый Player: 54744, 56838, 20; у первых двух воспроизведение повторено на публичном origin. **1 458** новых относительно прежнего индекса ID — потенциальное расширение, а не 1 458 видеопроверок. Тесты мобильного браузера — WebKit-эмуляция, не физический телефон.

Синхронизация кандидатов подготовлена, но автоматическое расписание не включено: договорные числовые лимиты/expiry неизвестны, а upstream total расходится на 9 записей. Новые номера серий вне сохранённого индекса требуют очередного обновления метаданных. Для работы текущего публичного API ключ/секрет/сервер не потребовались. Все 2 736 аниме и 43 776 номеров серий не проигрывались; источник показывается по актуальному ответу playlist и проверке разрешённых URL.
