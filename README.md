## Каталог, поиск и страницы

- Главная содержит только небольшие подборки; каталог сначала отдаёт **24 карточки**, остальные создаются по запросу. Полного каталога в DOM нет.
- Поиск по русским/английским/японским/альтернативным названиям работает по всему импортированному индексу. Индекс загружается при вводе, обрабатывается в Web Worker. Поставляется готовый gzip `search-index.bin`, распаковываемый стандартным DecompressionStream; JSON — запасной формат. При обычном открытии главной индекс и подробности не скачиваются.
- В индексе только поля поиска/карточек/фильтров. Подробности — отдельные `/data/anime/ID.json`, разрешения/URL изображений — отдельный `image-index.json`. Избранное загружает лишь нужные небольшие пакеты карточек, максимум три запроса параллельно.
- Сохранены все **3000 прежних SEO-адресов**. Остальные аниме открываются через `/anime/?id=ID`: прямой вход и перезагрузка работают на статическом хостинге. Данные берутся из локального JSON, не из API при открытии страницы.
- Избранное v2 сохраняет постоянные ID, миграцию v1, неизвестные записи и синхронизацию вкладок. Отказ поиска не мешает сохранению.
- Детали показывают реальные оценки Shikimori, студии, жанры, статус, эпизоды, даты и связи. Для неизвестных значений — прочерк/честное сообщение. Чужие описания автоматически не копируются.

## Синхронизация

```sh
npm run sync:full
npm run sync:anime
npm run sync:anime -- --ids=1,5114
npm run test:api
```

`sync:full` обходит **все** доступные типы/статусы/годы, `order:id`, `censored:false`, по 50 записей до конца, затем независимо сверяет `order:id_desc`, восстанавливает обнаруженные пропуски и проверяет связанные ID. Включает фактические метаданные возрастных категорий API; изображения/описания/видео при этом не публикуются. Скрытые/удалённые записи API перечислить не позволяет.

Кеш хранит проверенные пакеты; повтор продолжает с них. 1 запрос/с, тайм-ауты, 429/Retry-After и ограниченные повторы. Прогресс находится в `.cache/shikimori/full-progress.json`; рабочий snapshot заменяется атомарно только после проверок. Отчёт — `src/data/catalog-coverage.json`, предыдущий снимок — локальный `.previous`. `--force` игнорирует кеш, но создаёт существенную нагрузку: не использовать без причины. У полного режима нет рейтингового ограничения 3000/5000.

`sync:anime` — адресный maintenance: новые/изменённые записи, текущий и предыдущий сезоны, вращающаяся группа активных/недавних записей. Бюджет 80 пакетов, без удаления прежних ID. Полный аудит — `sync:full`, ежедневно он не повторяется. Для sync необходимо задать зарегистрированный `SHIKIMORI_USER_AGENT`. После sync перезапустите dev, чтобы файловый снимок перечитался. Обычный build offline и к API не обращается.

Импорт выполнен с User-Agent AniRezik. Перед регулярной эксплуатацией владелец должен зарегистрировать OAuth2-приложение Shikimori и задать его имя в `SHIKIMORI_USER_AGENT`. Проверенный endpoint — `https://shikimori.io`; токен для публичных читаемых полей в этом прогоне не потребовался.

Карточки используют единый жёлтый рейтинг с реальным score и источником в tooltip/ARIA, Footer/About. [Документы и ограничения](docs/POSTER_RIGHTS.md).

```sh
# В другом терминале, пока dev работает:

```

Откройте `http://127.0.0.1:4321/`. Команда включает `ANIREZIK_EXPERIMENTAL_SHIKIMORI_POSTERS=1` только для своего процесса. Обычный `npm run dev` сохраняет публичную политику. Эксперимент работает только в dev, вне CI и на loopback; production игнорирует флаг даже со значением 1. Не публикуйте dev-сервер. Браузерная выборка **30/30 настоящих постеров** декодировалась, повторная загрузка использовала кеш, запросов к API — 0. [Отчёт](docs/research/remote-posters-local.json).

`image-sources.json` содержит область разрешения all/ids/точных URLs. Для Shikimori сохранены evidence скриншота, exact HTTPS origin и `browserCachePolicy:http-response-headers`; `browserCaching:null` не выдаётся за разрешение собственного хранилища. Реестр индивидуальных разрешений `image-rights.json` сохраняется. `poster.mainUrl` используется в карточках, `poster.originalUrl` — в деталях; имена/хеши не конструируются. Unknown не включается.

`RemotePoster` и клиентский рендерер поддерживают разрешённые HTTPS URL, lazy loading, async decoding, размеры 400×600, cover, однократный fallback без бесконечных повторов и без crossorigin. Независимые поля `posterUrl`/`backdropUrl`/`imageSource`/`imageAttribution`/`imageLicenseStatus` разрешаются через `image-rights.json`; unknown не включается. Вертикальное изображение не выдаётся за широкий арт: при отсутствии backdrop используется подписанный размытый фон либо нейтральный градиент.

## GitHub Pages

1. Загрузить существующий проект в репозиторий через Git; `node_modules`, `dist`, `.cache` не коммитить. `src/data/catalog.json` и отчёт покрытия нужны в репозитории.
2. Settings → Pages → Source: GitHub Actions. В ndokcorp/anirezik источник уже настроен; workflow определяет site/base, проверяет код, собирает, тестирует и публикует после успеха. Ссылка на удалённые результаты приведена выше.
3. Для собственного домена задать Actions Variables `SITE_URL=https://ваш-домен`, `BASE_PATH=/`. Для репозитория OWNER.github.io также base `/`.
4. Обновление данных выключено до `SHIKIMORI_SYNC_ENABLED=true` и зарегистрированного `SHIKIMORI_USER_AGENT`. Ежедневно maintenance, ежемесячно full audit; ручной запуск предлагает оба режима. Общая цепочка check/build/unit/трёх браузеров публикует только проверенные метаданные, не код/workflows. Регистрация приложения ещё не подтверждена, поэтому расписание не активировано. [Точные шаги включения и ограничения](docs/SMART_SYNC.md).

Локальная проверка подпути (переменные читает Astro config):

```powershell
$env:SITE_URL='https://example.github.io'
$env:BASE_PATH='/anirezik'
npm run build
npm test -- --project=unit --project=chromium --project=webkit
Remove-Item Env:BASE_PATH
Remove-Item Env:SITE_URL
npm run build
```
